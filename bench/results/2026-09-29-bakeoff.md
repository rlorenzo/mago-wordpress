# 2026-09-29 bake-off: top 10 WordPress.org plugins + WordPress core

`bench/bakeoff.sh` (phpcs WordPress-Extra vs mago + mago-wordpress), mean of 3 runs after a warm-up.
Versions: mago 1.50.0 / PHP_CodeSniffer version 3.13.6 (stable) by Squiz and PHPCSStandards, PHP 8.4.24, this package at v1.0.1-4-g3b2ce2b.

Run on the `support-cutoff` branch: `minimum-wp-version` now defaults to 6.7 (WPCS 3.4.1's
default; was 6.0) and `wordpress/posix-functions` was dropped. Machine load average was 6–7.
Per-rule counts differ from the 2026-09-28 bake-off in exactly the ways the new default predicts:

- `wordpress/prepared-sql-placeholders`: WooCommerce 39 → 0, Yoast SEO 33 → 0, Contact Form 7
  3 → 0, WordPress core 5 → 0. Every one was an `%i` placeholder reported as unsupported
  before WP 6.2; with the minimum at 6.7 the `%i` placeholder is valid, as WPCS also concludes.
- `wordpress/wp-deprecated-functions` on WordPress core: 47 → 79, `wp-deprecated-classes` 7 → 8.
  Deprecations between WP 6.0 and 6.7 are now reached.
- Every other rule on every codebase: unchanged.

Timings here are 10–20 % faster than 2026-09-28 for both tools; no code on the timed path changed,
so the README keeps the 2026-09-28 figures.
